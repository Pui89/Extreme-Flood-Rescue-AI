# Engineering Requirements and Evidence Matrix — Flood Rescue AI

**Last reviewed:** 2026-10-23  
**Default-branch baseline inspected:** f7ea7ec9adb6cb8f6716d65fed7a369ec8b534c9  
**Scope:** simulation-first flood reconnaissance and rescue decision support. This matrix is an internal engineering aid, not a claim of real-world rescue capability or standards compliance.

## Evidence and status rules

- **Verified** means the named software check completed successfully within its stated scope.
- **Failed** means a check ran and did not meet its criterion.
- **Not measured** means the required evidence is unavailable; do not infer a pass.
- Synthetic software demonstrations, navigation simulation, and physical field trials are separate evidence classes.
- A passing CI job is not proof of victim detection, safe route execution, or successful rescue.

## Maturity gate and next step

**Current maturity:** software prototype with selected regression/safety checks; the latest main-commit full Python matrix was pending at review time. Not an evaluated rescue system.

**Largest blocker:** no frozen, lawful, labelled task dataset or measured scenario set.

**Highest safety risk:** treating unknown flood terrain or a supplied collision flag as proof of safety.

**Next gate:** finish current-HEAD CI, then run a deterministic local simulation scenario suite with a baseline, denominator, collision/hazard counts, recovery outcomes and JSON artifacts. Keep all results separate from physical field trials.
